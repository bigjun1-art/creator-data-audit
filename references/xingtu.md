# 巨量星图适配

验证时间：2026-07-25。这里以此前两次完整跑通的任务作为黄金路径；第三次逐页点击失败只沉淀为熔断条件，不作为执行方案。

## 两次成功任务的黄金路径

两次成功任务共同使用了同一条链路：

1. 从当前源表和最新版飞书模板生成本次运行配置，不复制旧达人数组、旧 workbook token 或旧列号。
2. 复用用户已经登录的同一个 Chrome 星图页面，在 `www.xingtu.cn` 同源上下文中一次性执行参数化批量代码。
3. 代码依次调用搜索、基础资料、最新作品接口；先找候选星图ID，再用平台昵称和主页 `unique_id/short_id` 双重核验，最后取最近15条作品播放量与发布时间。
4. 每 3 到 5 人保存成功、歧义、失败清单和检查点；断点后只补失败项及未处理项。
5. 后台数据落地后在本地统一校验、计算最低/最高/平均播放量，并生成带真实日期的证据图。
6. 飞书阶段通过 `lark-cli` 串行创建、写值、逐张上传图片并回读首尾行和异常行。

这条链路的核心不是“鼠标自动点击”，而是“一次同源代码执行完成整批后台取数”。批量任务不得改写为逐达人搜索、逐达人开主页或逐达人开标签页。

本 Skill 已把黄金路径固化为可执行文件：

- `scripts/discover_latest_lark_template.py`
- `scripts/prepare_run.py`
- `scripts/xingtu_page_runner.template.js`
- `scripts/validate_capture.py`
- `scripts/make_evidence_charts.py`
- `scripts/write_lark_sheet.py`

真实任务直接运行这些入口。除非接口明确返回结构变化，否则不重新探路、不重新写临时爬虫。

## 已验证字段

- 地区（主页显示则取值，未显示留空）
- 达人名称、抖音号或原达人ID
- 星图内部达人ID
- 星图粉丝数
- 达人类型、内容主题
- 最近作品播放量及作品发布时间

## 已验证后台请求

- 搜索：`POST /gw/api/gsearch/search_for_author_square`
  - 变化参数：`search_param.keyword`
  - 先输入原达人ID，再输入达人名称；ID搜索得到候选但未通过双重核验时，必须继续名称搜索。
- 基础资料：`GET /gw/api/author/get_author_base_info`
  - 变化参数：`o_author_id=<星图ID>`
  - 核验字段：`nick_name` 与 `unique_id/short_id`。
  - 地区按 `city_name/city/region_name/region/location/area/province_name/province` 的已返回值依次取首个非空；能力截图页再从主页“地区”标签回补。两处都无值就留空。
- 最近作品：`GET /gw/api/author/get_author_latest_items`
  - 变化参数：`o_author_id=<星图ID>`、`limit=15`
  - 保存字段：作品ID、播放量、发布时间、标题。

响应内16位及以上整数必须先转字符串再解析，避免 JavaScript 把星图ID舍入。执行器已经包含无损处理，禁止删除。

## 参数化批量执行

批量任务默认使用参数化后台路径，单达人页面流程只用于首次验证和必须的网页截图。

1. 运行前解析配置：`source`、`target_spreadsheet`、`target_sheet`、`reference_sheet`、`column_map`、`creator_keys`、`requested_fields`、`screenshot_fields`、`batch_size`、`retry_limit`、`checkpoint_path`、`output_dir`。每次任务重新解析，不沿用旧表 token、sheet ID、列号或达人数组。
2. 直接使用已经固化的请求方法、参数位置、响应字段和身份对应关系。只有接口明确报结构变化时，才允许用一个样本重新确认并更新模板。
3. 参数化变化项，而不是复制页面步骤：
   - 搜索模板输入名称或原达人ID，输出候选星图ID；
   - 基础信息模板输入星图ID，输出昵称、主页唯一ID、粉丝数、达人类型和内容主题；
   - 最近作品模板输入星图ID，输出同一批作品的播放量和发布时间。
4. 默认 `batch_size=3..5`、并发数为 1；同一批复用一个 Chrome 绑定和一个同源后台通道。只有当前样本证明平台稳定且未出现取消、验证码或风控时才调整批次大小。
5. 在页面同源上下文中一次运行生成的 `xingtu-page-runner.js`，由执行器在内存中循环并只保存所需字段；禁止一达人一标签页。
6. 每批写入检查点：`completed_ids`、`ambiguous_ids`、`failed_ids`、`attempts`、请求模板版本和抓取时间。重启后只读取 `failed_ids` 和未处理 ID；接口结构变化只重抓一个样本并升级模板版本。
7. 后台结果先在本地完成身份双重核验、数值统计和证据图生成，再批量写飞书。网页能力截图另建截图队列，按类目存在性逐项执行，不让截图流程拖回逐达人取数。
8. 批量写入后回读首行、末行、所有歧义/失败行和至少一行图片；只有回读计数与检查点守恒才完成任务。

不要硬编码 Cookie、鉴权头或用户身份信息。路径或参数失败时重新捕获一个真实样本，不连续猜参数。

不要用独立 Playwright、外部 Chromium、Computer Use、鼠标点击或多个手工标签页替代已登录 Chrome 的同源后台执行。若取不到同源代码执行通道，先按 Chrome Skill 的故障指引恢复；仍失败则停止并明确报告，不能退化成逐个页面采集。这只是第三次失败留下的熔断保护，不是黄金流程的一部分。

## 星图核验口径

- 有原达人ID：平台昵称与主页唯一ID同时匹配才标记已核验。
- 无原达人ID：名称精确匹配优先，结合原表粉丝量排除明显错误候选，再回填后台ID。
- 星图ID是星图内部达人标识，不等于原表达人ID/抖音号。记录两者的字段名与来源，禁止互相替代。
- 表情后缀可标准化后比较，但表中同时保留原昵称与平台昵称。
- 播放量默认使用平台返回的最近作品明细；图内显示月日和整体日期范围。

## 飞书写表与截图口径

- 飞书电子表格只用 `lark-cli sheets` 读取、建子表、写值、上传单元格图片并回读；浏览器保留给星图查询。
- 先执行 `lark-cli auth status --json --verify`，核对正确用户、`open_id`、`tokenStatus=valid` 和 `refreshExpiresAt`。授权检查、写值、上传图片全部串行运行，并确保用户凭据目录可写。
- 若刷新令牌报 `20073` 或 `20064`，先排查受限沙箱导致的加密凭据写入失败；不要把它误判为用户刚授权就失效，也不要反复要求重新授权。
- 先从参考子表读取真实列名和顺序，不凭记忆重建表头。保留原表粉丝、费用等字段。
- 常用核查列以“地区”为第一列，之后是达人名称、达人ID/抖音号、星图ID、星图粉丝数、达人类型、内容主题、创作能力-播放量截图、最低播放量、最高播放量、平均播放量、核验状态，以及用户指定的能力截图列。地区只取主页或后台明确显示值，不根据活动城市推断。
- 既有表补“地区”列的已验证飞书 CLI 路线：先回读并保存 A1:A末行；`+dim-insert --position A` 会在 A 后生成空白 B；随后写地区到 A、把保存的达人名称写回 B。验收必须同时满足 A1=`地区`、B1=`达人名称`、名称行数守恒、原截图列整体右移一列且 `embed-image` 数量不变。
- “达人概览、商业能力、创作能力、履约能力、连接用户”先读顶部标签判断是否有独立入口，再逐列截图；没有显示就留空，禁止用相邻标签内容补位。
- 顶部标签只用于判断存在性，不进入最终截图。截图裁掉网站顶栏和顶部类目标签，只保留用户样例要求的完整数据内容区；目标内容超出视口时处理滚动和懒加载后截取完整元素，禁止半截图。
- 截图前验证当前激活标签、页面标题/关键卡片和非空数据；验证失败则该列留空或标记待重试，不上传错标签、加载中或空白截图。
- `创作能力-播放量（截图）` 与 `创作能力` 分开处理：前者使用最近15条作品及对应日期生成证据图，后者保存平台创作能力页实际显示的数据内容。
- 写入单达人样例后至少回读：达人名称、星图ID、播放量四列、能力截图列；确认图片尺寸和空列状态后再交用户验收。

## 2026-08-05 能力截图黄金路径

使用 `scripts/xingtu_ability_capture.mjs`，不要重新编写页面循环。输入已核验记录、最新版列和输出目录后，脚本对每个星图ID直接打开主页，读取顶部真实 `tab`，仅对存在的类目点击并截图；地区从主页“地区”标签提取。截图固定裁切 `.tabs-content`，不含顶部标签栏；视口宽度 1920，高度按内容从 2200 动态扩展，最大 6000，以覆盖图表、视频列表和懒加载区域。每完成一人立即写 `ability-checkpoint.json` 与 `ability-image-manifest.json`。

截图完成后，新表把播放量清单和能力清单同时交给 `write_lark_sheet.py`；已存在的表使用 `upload_lark_images.py` 串行补传，禁止重建表。验收时用 `+cells-get` 回读五个能力列的 `embed-image` 数量：实际图片数必须等于页面真实存在且成功加载的标签数；不存在的标签列保持空白。

## 固定执行桥（2026-08-08）

真实任务不再由 Agent 临时拼接 Chrome 代码。先运行 `run_creator_audit.py prepare`，它会生成本次 `chrome-job.mjs`；按 Chrome Skill 初始化一次现有 Google Chrome 后，只导入该文件并调用 `default(chrome)`。作业内部固定调用 `xingtu_chrome_bridge.mjs`，完成星图标签认领、同源后台批量请求、失败项合并续跑、`xingtu-capture.json` 直接落盘、真实能力标签截图、地区回填和标签释放。后台阶段不会触发浏览器 JSON 下载，也不使用鼠标或 Computer Use。

桥接作业完成后只运行 `run_creator_audit.py finish`。该命令校验记录守恒、生成日期播放量证据、合并播放量与能力图片清单，并在提供 `--folder-token` 与 `--title` 时调用飞书发布脚本。`status` 子命令用于中断后判断下一步，禁止仅因新对话重新执行已完成阶段。

## 批量验收清单

1. 源表行数等于 `已核验 + 未唯一匹配 + 请求失败待重试`，核验状态不得留空。
2. 每个 `已核验` 行同时通过平台昵称和原达人ID/主页唯一ID校验；无原ID时回填找到的真实ID并保留核验依据。
3. 最近15条播放量的最低、最高、平均值与证据图一致，图中日期和覆盖范围可见。
4. 能力截图数量等于页面实际存在并成功加载的类目数量；缺失类目对应单元格为空。
5. 回读首行、末行和所有异常行，检查昵称表情、原ID、星图ID、粉丝数、四个播放量字段、能力图片及空白列。
6. 回读确认第一列表头为“地区”；已显示地区的已核验达人有值，未显示和未唯一匹配行为空。
6. 最终只报告完成数、未匹配名单、失败名单、图片总数和飞书链接；没有通过回读不得声称完成。

## 已知风控

- 出现验证码立即交给用户，不由代理尝试完成。
- 使用稳定小批次，只重试被取消或失败的达人。
